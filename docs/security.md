# Security

Usool is a single-PC application, but it is built as if the port could be reached by other software on the machine or a hostile web page.

## Network
- The server listens on `127.0.0.1` only. Requests whose `Host` header is not `127.0.0.1`, `localhost` or `[::1]` are refused
  (DNS-rebinding protection).
- For state-changing methods the `Origin` header, when present, must have the same host and port; the custom header
  `X-Requested-With: GooyaAsset` is mandatory (a page on another site cannot set it without a CORS pre-flight, which the server never allows).
- Responses carry `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`; HTML also gets a
  Content-Security-Policy (`default-src 'self'; script-src 'self'`, no inline scripts).
- Request bodies are limited (60 MB, attachments) and must be JSON objects for JSON endpoints. Unexpected errors return a generic 500 and are logged
  server-side only.

## Sign-in and sessions
- First run with no users: the sign-in page offers to create the administrator (one time only).
- Passwords: at least 8 characters with letters and digits; stored as PBKDF2-SHA256 (200 000 rounds, per-password random salt), compared in
  constant time.
- Login throttling: 5 failed attempts lock the account for 10 minutes; unknown user names are throttled the same way and receive the same
  message, so the server never reveals whether a name exists. An administrator can unlock a user.
- Session token: random, only its hash is stored; cookie `gooya_session` is `HttpOnly; SameSite=Strict`, expires after 12 hours idle or 7 days
  total. Changing a password or deactivating/deleting a user ends that user's other sessions.
- A user flagged "must change password" can call nothing else until the password is changed.

## Authorisation
- Every API call is checked in one place: `auth.required_permission(method, path)`; unknown paths require `users.manage` (default deny).
  Settings writes are additionally checked per key (backup keys need `backup.manage`, the rest `settings.manage`).
- Permissions (21): assets.view/edit/delete/dispose, depreciation.view/run/post, periods.manage, maintenance.view/edit, contacts.view/edit,
  custody.view/manage, reports.view, inquiries.view, audit.view, settings.view/manage, backup.manage, users.manage.
- Standard roles: **Administrator** (all, fixed), **Asset Accountant**, **Asset Officer**, **Viewer**; more roles can be created in Settings.
- The Administrator role always exists; the last administrator cannot be deleted, deactivated or demoted.
- Data minimisation: without `custody.view` the asset payload hides the custodian and the signed custody forms; without `backup.manage`
  the lookup response hides folder paths and backup state.
- The interface hides what a user cannot do, but hiding is never the control — the server refuses.

## Branch scope
- Users can be limited to branches (`tbl_UserBranches`). Every request starts with nothing in scope; after sign-in the server sets the
  user's branches, narrowed by the `X-Scope` header of the branch picker, and asking for another branch never widens it
  (`apply_scope` in `app/services/branches.py`). Every asset query adds `scope_sql()`, so an asset outside the scope answers 404.
- `tests/test_scope.py` checks this over HTTP, including that a scope never carries over to the next request on a reused thread.

## Data
- Attachment and backup file names are generated by the server (never taken from the client path); paths are resolved and confined to the
  configured folders; restore (`tools/restore_backup.py`) rejects archive entries that would leave the target folder.
- CSV exports neutralise cells that start with `= + - @` (spreadsheet formula injection).
- All changes are written to the audit log with the acting user; scheduled work runs as `system`.

## Operating advice
- Keep the backup folder on another disk or a synced folder, and test a restore occasionally.
- Do not expose port 8742 through a firewall rule or a tunnel; if multi-user access is needed, put a reverse proxy with TLS in front and
  review this document first.
